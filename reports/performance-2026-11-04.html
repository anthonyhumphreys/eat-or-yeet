What these numbers establish

The implementation reduces the initial JavaScript payload and improves the sampled local loading results. Three runs are a small sample; timing changes are directional. This review does not establish production Core Web Vitals, low-end physical-device performance, cold-cache behavior, or real-user INP.

What changed

Official advice streams first

Recall detail pages render their title, advice, affected products and official-source link while related publisher news loads inside its own Suspense boundary. A regression test holds the news promise open and verifies the advice remains available.

The list stays put as news arrives

The phone’s “See the news” shortcut is present immediately. It no longer waits for a publisher count before inserting above the filters. Recalls and news retain independent loading and failure states.

Optional code arrives when needed

Analytics validation loads after consent, with consent checked again before transmission. Verdict displays and the scanner’s optional label form load on demand. Empty form values no longer import the request schemas into initial checking routes.

Repeated list work is reduced

Memoized recall rows avoid rendering again for unchanged props, and absolute date formatting is retained between query updates. Search remains synchronous; filter changes and “Show more” keep their existing transitions.

Waiting is clear and bounded

Scanning and manual entry share one request lifecycle. Requests time out after 20 seconds and cancel on country changes or navigation. HTML gateway errors become a useful retry message. Form values remain available after failure.

Small details carry the brand

A restrained barcode sweep acknowledges a pending scan without inventing progress. It respects reduced motion and pauses in hidden tabs. Recall loading placeholders better match the destination, and restored list pages keep their page number in the URL.

Test quality and verification

The existing suite mostly exercises meaningful behavior: warning matching, source coverage, revision handling, privacy boundaries and integration contracts. Broad deletion would have weakened it. Cleanup focused on a few brittle assumptions.

  • Removed a cache migration test pinned to obsolete internal version names.
  • Replaced network-idle waits, a timed camera denial, and a global timer monkeypatch with visible readiness, a controllable permission failure and Playwright’s clock.
  • Scoped request checks to the relevant route and excluded background prefetches. Scoped alerts to main content so Next.js’s route announcer does not masquerade as an application error.
  • Made ordinary browser tests start with analytics declined, while explicit consent tests control their own choice. Default test-server settings use a fixture token.
  • Excluded private local-backup artifacts from lint and TypeScript checks.
  • Added regressions for stalled news, consent withdrawal during lazy loading, strict analytics payloads, deep list restoration, country-change cancellation, gateway errors and timeout recovery.
  • 642 unit tests passed68 files. Baseline: 639 tests across 66 files. One obsolete test removed; four focused unit regressions added.
  • 96 browser tests passedMobile and desktop Chromium. Six Notion-enabled cases skipped because that feature configuration was unavailable. Repeated rapid-typing checks also passed.
  • Production build passedNext.js 16.4.2, using its installed documentation for streaming, loading and lazy-loading behavior.
  • TypeScript and lint passedNo type errors, lint errors or warnings in the checked codebase. Whitespace validation passed. The Impeccable detector reported seven advisory findings in existing type sizes and scanner-frame styles; no new design-system drift was introduced.
  • Visual and motion checks390 px phone, 320 px narrow viewport and 1280 px desktop captures; light and dark themes; reduced-motion browser coverage.

Remaining performance work

  1. The US browse snapshot is still the largest cost. The sampled page previously carried about 2.27 MB of uncompressed HTML/RSC output (about 433 KB when gzipped). It sends a complete regional snapshot to support local filtering. A future change could separate the first visible page from full search data, with explicit revision handling and correct category counts.
  2. Measure production after deployment. Capture real-user LCP, INP and CLS by route and device. Repeat cold-cache and poor-connectivity checks against the deployed edge and data services.
  3. Verify physical devices and additional engines. This pass used emulated Chromium on the development machine. iPhone Safari, lower-end Android hardware and extended screen-reader checks remain outside the measured evidence.
  4. Enabled Notion installation coverage remains configuration-dependent. Its six mobile/desktop cases were skipped by the existing feature-configuration guard. The disabled-entry behavior and other integration tests ran.

Repeat the measurements

Build and start the app against a working local backend, then run the added profiler. It saves every sample and resource entry as JSON, uses a fresh browser context per run and declines optional analytics.

pnpm build
pnpm start --port 3100

# In another terminal, while no other browser suite is running:
PERF_BASE_URL=http://localhost:3100 \
PERF_DETAIL_PATH=/incidents/fsa-fafa-03-2026 \
pnpm perf:web out/web-performance.json

The detail path above names the recall used for this comparison; choose another existing recall when needed. The profiler defaults to three runs; PERF_RUNS accepts 1–10. Playwright Chromium must be installed. For an externally started E2E server, supply the fixture analytics settings documented in playwright.config.ts.
